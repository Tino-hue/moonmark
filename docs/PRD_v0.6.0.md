## 一、项目背景

### 1.1 项目定位

MoonBit Depsight 是 MoonBit 生态的依赖健康诊断 CLI 工具，定位类似 Rust 生态的 `cargo audit` / Node 生态的 `npm audit`。读取 `moon.mod`，递归遍历整个传递依赖图，为每个包计算 0-100 的健康评分，并提供可操作的诊断信息。

**一句话 slogan**：给你的 MoonBit 依赖做一次全身体检。

### 1.2 当前状态

- 版本：v0.5.3（已发布至 mooncakes.io）
- 测试：267 个用例，全部通过
- 文档：架构设计、使用手册、性能基准、CI 集成等 6 篇文档
- 功能：5 维健康评分、5 种输出格式、5 个便捷命令
- 自审计健康分：98/100

### 1.3 参赛目标

参加 9 月黑客松「社区项目赛道」，角逐季度优秀项目。核心目标：

1. **完成度提升**：修复现有"半实现"功能，把占位符变成真功能
2. **亮点强化**：突出"跨包废弃 API 传播"等首创功能的展示效果
3. **体验优化**：打磨用户体验细节，提升专业度
4. **演示效果**：增强示例项目和输出展示，提升视觉冲击力

## 三、功能需求

### 3.1 F01：总 API 数统计 & 废弃密度准确计算

**优先级**：P0（必做）

**问题现状**：

- `analyzer.mbt` 第 98 行 `total_api_count=10` 硬编码
- 废弃密度 = 废弃API数 / 10，完全不准确
- 导致健康评分中"废弃密度"维度参考价值低

**需求描述**：

1. 在 `package_scan.mbt` 中新增 `count_public_apis_from_dir()` 函数
2. 扫描所有 `.mbt` 文件，统计 `pub fn` / `pub let` / `pub const` / `pub struct` / `pub enum` / `pub trait` / `pub type` 的总数
3. 将总 API 数传入 `run_analysis()`，替换硬编码的 10
4. 废弃密度 = 废弃 API 数 / 总 API 数，百分比计算

**验收标准**：

- [ ] 总 API 数基于真实源码扫描，非硬编码
- [ ] 废弃密度评分随废弃 API 占比动态变化
- [ ] 新增单元测试覆盖 API 计数逻辑
- [ ] 现有 267 个测试全部通过

### 3.2 F02：传递体积接入主分析流程

**优先级**：P0（必做）

**问题现状**：

- `size.mbt` 中 `calculate_transitive_sizes()` 算法已实现

- 体积评分维度只看包自身大小，不考虑传递依赖体积

**需求描述**：

1. 在 `run_analysis()` 中调用 `calculate_transitive_sizes()` 计算所有节点的传递体积
2. 用传递体积替代自身体积进行健康评分
3. 在终端报告中增加"Top 5 体积罪犯"输出模块
4. HTML 报告中增加体积归因展示

**验收标准**：

- [ ] 体积评分基于传递体积而非自身体积
- [ ] 终端报告显示 Top 5 体积最大的依赖

## 四、技术方案

### 4.1 架构影响

本次优化不改变现有分层架构，主要在现有模块内增强功能：

```
cli/           ← 新增 stats 命令、版本常量
analyze/       ← 传递体积接入、废弃传播可视化、API 计数
graph/         ← 无改动
fetch/         ← 无改动
parse/         ← 无改动
report/        ← 新增 DEPRECATED-002 诊断码
cache/         ← 新增 path_join 方法
```

### 4.2 关键技术点

#### 4.2.1 总 API 数统计

复用 `deprecated.mbt` 中的 `extract_definition_name()` 逻辑，新增 `count_public_apis(source: String) -> Int` 函数。扫描策略：

- 逐行扫描 `.mbt` 文件
- 匹配 `pub fn` / `pub let` / `pub const` / `pub struct` / `pub enum` / `pub trait` / `pub type`
- 排除测试文件（`_test.mbt` / `_wbtest.mbt` / `_bench_test.mbt`）
- 排除注释行和 doc comment 中的伪匹配

#### 4.2.2 传递体积集成

在 `run_analysis()` 中：

1. 先收集所有节点的 `self_size`，构建 `Map[String, Int]`
2. 调用 `calculate_transitive_sizes(graph, self_sizes)` 得到传递体积 Map
3. 逐节点评分时从传递体积 Map 中取值

Top N 体积罪犯输出复用 `find_size_offenders()` 函数。

#### 4.2.3 废弃传播可视化

`deprecated_propagate.mbt` 中已有 Reverse-BFS 逻辑，需要增强：

1. 记录每个废弃 API 的传播路径（从源包到直接依赖的路径链）
2. 区分"本包定义的废弃"和"从依赖暴露的废弃"
3. 传播路径数据结构：`{ api_name, source_package, path: Array[String] }`

### 4.3 兼容性

- 所有现有命令和输出格式保持向后兼容
- 新增的 `stats` 命令不影响现有命令
- 新增的 `DEPRECATED-002` 诊断码是补充，不改变 `DEPRECATED-001` 的语义
- 健康评分算法调整可能导致分数变化，属于预期内的"更准确"

| 操作系统           | Windows 10+ / macOS 12+ / Ubuntu 20.04+，三平台 CI 验证通过            |
| 终端兼容           | 支持 ANSI 颜色代码（Windows Terminal、iTerm2、Terminal.app、VSCode）   |
| 颜色关闭回退       | `NO_COLOR` 环境变量或非 TTY 时，纯文本输出无 ANSI 乱码                 |

### 9.3 安全性需求

| 需求项        | 要求                                                                     |
| ------------- | ------------------------------------------------------------------------ |
| 路径安全      | 所有文件读取禁止 `../` 路径穿越，缓存目录限制在用户家目录下              |
| HTTP 白名单   | 仅允许请求 `*.githubusercontent.com` / `api.github.com` / `mooncakes.io` |
| Token 保护    | CI 中所有访问令牌通过 GitHub Secrets 注入，绝不硬编码或写入日志          |
| 缓存 TTL 验证 | 读取缓存前必校验时间戳，超过 24h 强制回源                                |
| 输入长度限制  | CLI 参数、配置文件字段有合理上限（如诊断码 ignore 列表 ≤ 100 项）        |
| 许可证合规    | 项目自身 Apache-2.0；仅引入 moonbitlang/core（MIT/Apache 双许可）        |

### 9.4 可用性需求

| 需求项     | 要求                                                                    |
| ---------- | ----------------------------------------------------------------------- |
| 离线可用   | `--offline` 模式下不发起任何网络请求，仅使用本地缓存，功能降级正常      |
| 优雅降级   | 网络失败、文件缺失、包解析失败时给出中文可读错误，不抛出未捕获异常      |
| 帮助信息   | 所有命令支持 `--help`，输出包含用法、选项、示例；零参数默认打印帮助     |
| 退出码约定 | `0`=成功 / `1`=审计触发阈值 / `2`=参数错误 / `3`=内部错误 / `4`=IO 错误 |
| 诊断四要素 | 每条诊断包含：严重级（Critical/Warning/Info）+ 诊断码 + 描述 + 修复建议 |
| 进度反馈   | 大型项目（>50 节点）分析时输出进度 spinner 或阶段提示                   |

### 9.5 可维护性需求

| 需求项         | 要求                                                                    |
| -------------- | ----------------------------------------------------------------------- | ------------------------------------- |
| 单一职责       | 单文件不超过 500 行，超长文件按职责拆分（参考 cli.mbt 后续拆分方向）    |
| 可测试性       | 所有 I/O 操作走接口抽象（FileSystem / Registry），实现可 mock 版本      |
| 扩展模式       | 新增输出格式 = 新 `*_reporter.mbt`；新诊断维度 = 新 `*_diagnoser.mbt`   |
| 代码风格门禁   | 所有 PR 必过 `moon fmt --check` + `moon check --target js --deny-warn`  |
| 文档注释规范   | 公共 API 必须带 `///                                                    | ` doc comment；复杂算法附中文步骤说明 |
| 版本号单点定义 | 语义化版本在 `cli/constants.mbt` 定义一处，moon.mod 与发布 tag 三向对齐 |

### 9.6 可扩展性需求

| 扩展点           | 设计                                                                   |
| ---------------- | ---------------------------------------------------------------------- |

## 十二、工程化治理配套

> 详细方案见同目录：[ENGINEERING_v0.6.0.md](./ENGINEERING_v0.6.0.md)

### 12.1 分支模型

采用 GitHub Flow + 三分支分级：

| 分支         | 用途                       | 推送权限        |
| ------------ | -------------------------- | --------------- |
| `main`       | 日常开发集成，所有 PR 合入 | 维护者 + 机器人 |
| `release/v*` | 版本候选（发布前冻结）     | 维护者          |
| `stable`     | 已发布的稳定版本锚点       | 仅 CI 机器人    |
| `feature/*`  | 单项功能开发               | 开发者个人      |
| `hotfix/*`   | 线上紧急修复               | 维护者          |

### 12.2 多仓库同步策略

- **GitHub = 单一可信源（SSOT）**：所有提交/PR/Issue/讨论仅在 GitHub 发生
- **GitLink / Gitee = 只读镜像**：CI 通过后由 `mirror-sync.yml` 自动推送 `main`/`stable`/`tags`
- 三平台默认分支统一为 `main`，清理历史 `master` 分支

### 12.3 质量门禁金字塔

```
                    ┌─────────────┐
                    │ Code Review │   ← 至少 1 人 Approve
                    └──────┬──────┘
                           │
                 ┌─────────▼──────────┐
                 │ 自审计 ≥ 85 / 无 C │   ← depsight audit
                 └─────────┬──────────┘
                           │
               ┌───────────▼────────────┐
               │ moon test (267+ 全绿)  │
               └───────────┬────────────┘
                           │
             ┌─────────────▼───────────────┐
             │ moon info 接口生成一致性    │
             └─────────────┬───────────────┘
                           │
          ┌────────────────▼──────────────────┐
          │ moon fmt --check  格式合规        │
          └────────────────┬──────────────────┘
                           │
        ┌──────────────────▼────────────────────┐
        │ moon check --deny-warn  类型零警告    │
        └───────────────────────────────────────┘
```
