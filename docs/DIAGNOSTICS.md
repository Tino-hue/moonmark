# MoonBit Depsight 诊断代码参考

本文件完整列出 Depsight 分析引擎可产出的全部诊断代码，供用户理解每条告警的含义、触发条件与修复建议，也作为 CI 中 `--ignore` / `.depsight.toml [severity]` 配置的权威参考。

## 概览

| 代码 | 默认级别 | 触发条件 | 参与健康评分 |
|------|----------|----------|--------------|
| `CYCLE-001` | Critical | 依赖图中存在循环依赖 | 否 |
| `LICENSE-001` | Warning | 使用高风险许可证（GPL/AGPL/SSPL） | 是（合规维度） |
| `LICENSE-002` | Info | 根/依赖未声明许可证 | 是（合规维度） |
| `DEPRECATED-001` | Warning | 包内直接包含 `@deprecated` API | 是（废弃密度维度） |
| `DEPRECATED-002` | Warning | 间接依赖通过传递链暴露废弃 API | 否 |
| `OUTDATED-001` | Warning / Info | 存在更新的版本可用 | 否 |
| `DUPLICATE-001` | Warning | 同一包名在图中有多个版本 | 否 |
| `UNUSED-001` | Warning | `moon.mod` 声明但源码从未 import | 否 |

> **级别说明**：`OUTDATED-001` 当升级跨越主版本（major）时为 Warning，其余（minor / patch / prerelease）为 Info。所有诊断的默认级别均可通过 `.depsight.toml` 的 `[severity]` 段覆盖。

---

## CYCLE-001 — 循环依赖

- **级别**：Critical
- **触发条件**：依赖图检测到环（例如 `A → B → A` 或自依赖 `A → A`）。
- **影响**：循环依赖会导致构建顺序不确定、打包体积膨胀，是 MoonBit 生态最严重的依赖健康问题之一。
- **修复建议**：沿诊断中给出的环路径，移除其中一条边以打破循环；若为自依赖，删除该条自引用。

---

## LICENSE-001 — 高风险许可证

- **级别**：Warning
- **触发条件**：依赖声明的 SPDX 许可证属于高风险 copyleft 集合（GPL-3.0、AGPL-3.0、SSPL-1.0 等）。
- **影响**：强 copyleft 可能污染下游项目的许可证合规，商业化 / 闭源场景需谨慎。
- **修复建议**：替换为 MIT、Apache-2.0 或 BSD-3-Clause 等宽松许可证的替代包。

---

## LICENSE-002 — 未声明许可证

- **级别**：Info
- **触发条件**：依赖（或根项目）的 `moon.mod` 未提供 `license` 字段。
- **影响**：法律上默认“保留所有权利”，无法确认可安全使用。
- **修复建议**：在 `moon.mod` 中添加 `license = "Apache-2.0"`（或实际采用的许可证）。

---

## DEPRECATED-001 — 直接废弃 API

- **级别**：Warning
- **触发条件**：包内源码的 doc comment 中扫描到 `@deprecated` 标注（`fn` / `let` / `const` / `struct` / `enum` / `trait`）。
- **影响**：废弃 API 可能在下个主版本被移除，继续使用会带来迁移风险。
- **修复建议**：升级到最新版本；参考包 changelog 中的迁移指南替换废弃调用。

---

## DEPRECATED-002 — 间接废弃传播

- **级别**：Warning
- **触发条件**：某个直接依赖（或更深层传递依赖）内部使用了废弃 API，并通过依赖链“暴露”给当前项目。
- **影响**：即使项目代码未直接调用，废弃 API 仍可能经由传递依赖影响运行稳定性。
- **修复建议**：优先升级传播链源头的包；诊断消息会给出完整传播链（`源 ⇒ 中间 ⇒ 当前节点`）逐跳可追溯。

---

## OUTDATED-001 — 依赖已过时

- **级别**：Warning（主版本落后）/ Info（次版本、补丁、预发布落后）
- **触发条件**：依赖存在比当前锁定版本更新的可用版本（来自注册表元数据或离线 mock 的 `_latest_version` 扩展字段）。
- **影响**：过时依赖可能缺失安全补丁或关键修复。本诊断不参与健康评分，仅作为可升级提示。
- **修复建议**：执行 `depsight outdated` 查看完整可升级清单；主版本升级前先阅读 breaking change 说明。

---

## DUPLICATE-001 — 同名多版本冲突

- **级别**：Warning
- **触发条件**：同一包名在依赖图中出现多个不同版本（版本约束冲突或依赖分叉导致）。
- **影响**：重复打包同包不同版本，增大体积并可能引入类型 / 行为不一致。
- **修复建议**：统一各依赖对同一包的版本约束到单一版本，消除重复。

---

## UNUSED-001 — 未使用的声明依赖

- **级别**：Warning
- **触发条件**：`moon.mod` 声明了某依赖，但项目源码的 `moon.pkg` / `moon.pkg.json` 中从未 import 该包（也未 import 其子包）。
- **影响**：冗余声明增加解析与构建负担，也让依赖清单失真。
- **修复建议**：从 `moon.mod` 移除不再需要的依赖；若确实使用但未被识别，请确认 import 写入了 `moon.pkg` / `moon.pkg.json`。

> **说明**：该检测仅在项目存在 `moon.pkg` / `moon.pkg.json` 时启用；纯 fixture 项目（无源码配置文件）会自动跳过，避免误报。
